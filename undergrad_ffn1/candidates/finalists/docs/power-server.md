# Selected-candidate RTL activity power on the server

Extract the complete upload under one directory. Source the server's Synopsys
environment so `dc_shell`, `vcd2saif`, and Python 3.6+ are on PATH, then run from
the extracted `optional_lab` root:

```bash
bash run_power.sh
```

This converts all twelve real, measured-window VCD files for each manifest case,
starts a fresh SoC synthesis per case, imports each task's SAIF **after compile**,
and writes `power_study/server/comparison.json`, `comparison.csv`, and
`comparison.md`. The compact tables include added/SoC area in library units,
mean strict cycles/task, measured throughput in task/s, weighted power in mW,
energy in uJ/task, setup/SS-only hold WNS in ns, and required coverage review.
Unknown metrics remain blank in CSV and `unknown` in Markdown. It uses the existing SS standard
cell/native SRAM `.db` paths under `$HOME/Desktop/lib`, the case's existing
`config/library_config.tcl`, optional local overrides, the existing 6.666667 ns
constraints, and `compile_ultra -no_autoungroup`. No `.lib` conversion occurs.
Missing libraries, unsupported commands/options, failed `read_saif`, changed
inputs, malformed timestamps, or mismatched duration cause an explicit failure.
The command stops on the first failed case; its logs and completed prior cases
remain on disk.

Useful partial commands:

```bash
bash run_power.sh --convert
bash run_power.sh --dc --collect --case flat_f0_p0_o0_w0_b1_d1_h0
bash run_power.sh --collect
python3 tools/power_server.py --help
```

`--dc` always starts fresh synthesis and includes conversion. A verified
conversion is reused only when VCD hash, duration, converter executable hash,
server tool hash, and SAIF hash all match. Partial/failed conversions rerun.
Fresh DC attempts live at
`power_study/server/<case>/<input fingerprint>/attempt_<UTC timestamp>/`.
Nothing in old cases, runs, DDCs, or vectorless reports is overwritten. Successful
DC attempts have `dc_complete.ok`; `latest.json` points only to the latest
completed attempt for the exact input fingerprint. `--collect` checks that
current source/config/capture signatures, SAIFs, resolved libraries, and raw
reports still match that attempt. It refuses changed or missing evidence.
Failed DC attempts can be inspected directly; restart with `--dc` to retry.
Progress lines flush immediately; DC output is streamed to the terminal and
saved to `launch.log` while the tool runs.

The study manifest is `power_study/activity_manifest.json` with
`cases: [{"name": "...", "path": "cases/..."}]`. Paths are relative
to the `power_study` directory containing the manifest. Each case provides
`output/activity/capture.json` with nonempty `source_signature`,
`config_signature`, `source_sha256` and `config_sha256` dictionaries (dictionary
paths relative to the case root), and twelve `tasks` numbered 0 through 11.
The receipt must have `passed: true`, `functional_passed: true`, and
`stage: "complete"`; running or functionally checked captures awaiting verified
VCD export are rejected.
`real_cpu` must be true, `task_count` must be twelve and `clock_period_fs` must
equal 6666667. The source/config signature digests are recomputed from their
hash dictionaries and each listed file is checked.
The nonempty `vector_sha256` map is checked against every listed case-relative
vector file; `output/firmware/kwt.hex` must match `firmware_sha256`.
Each task supplies `file` relative to the capture receipt directory, compressed
file `sha256`, integer `start_fs`, `end_fs`, `duration_fs`, and
`source_timescale_fs`. The server checks
the strict interval, streams the compressed VCD to check explicit timescale,
rebased timestamp zero and exact final duration, and checks converted SAIF
duration/timescale and `tb_soc/dut` scope. Fractional cycle counts are permitted;
energy uses the integer femtosecond duration directly.

Each attempt preserves:

- `netlist/*compiled.ddc` and `netlist/*.ddc`, SDC, SDF and SVF generated by the
  existing case synthesis/report flow, plus the original vectorless report.
- `report/activity/task_XX/annotation.rpt`, `coverage.rpt`, and `power.rpt` for
  each task. A successful `read_saif` marker is not a coverage pass.
- `report/saif_mapping.rpt`, `library_signatures.tsv`, `binding.json`,
  `report_signatures.json`, `launch.log`, and `activity_summary.json`.

`saif_map -start` runs before analyze/elaborate and tracking continues through
compile and name changes. Before **each** annotation the script executes
`reset_switching_activity`, then
`read_saif -auto_map_names -instance_name tb_soc/dut -verbose`. Bare
`report_saif` preserves the installed version's original coverage format;
`report_power -hierarchy` goes to that task's separate directory. Any command
incompatibility fails without falling back to vectorless activity. These command
forms are documented in the Synopsys-authored
[Power Compiler User Guide](https://users.ece.utexas.edu/~mcdermot/vlsi1/VLSI2_SP_2017/synopsys/doc/POWER_Compiler/pwr_cmplr_usr_gd.pdf).
The installed server release and licenses still need real-tool validation.

Data completeness, timing, and coverage review are separate fields. Coverage
always remains `required`; a human must inspect mapping, unannotated signals,
hierarchical CPU/accelerator activity and SRAM pin activity/model support in
the raw reports. Explicit annotation error/zero-annotation messages fail
collection, but the parser does not pretend to understand every release's
coverage format. Unsupported/unknown coverage formats remain for review.
There is no automatic coverage percentage threshold or fabricated pass.

Power is parsed through the existing `tools/ppa_metrics.py` routines, preserving
unknown units/metrics as JSON `null`. Dynamic plus leakage uses their respective
reported units; the hierarchical table's total column is retained as raw report
evidence rather than assuming leakage has the dynamic unit scale. With all
twelve tasks present, for each dynamic/leakage/total component:

```text
weighted power [W] = sum(P_i [W] * T_i [s]) / sum(T_i [s])
mean task energy [J] = sum(P_i [W] * T_i [s]) / 12
```

Any missing task/tool marker/power metric leaves the aggregate unknown.
`setup_meets_target` comes separately from fresh setup timing reports. The
strict captured interval ends at the final DMA write response; historical
mailbox-observed cycle counts are a different timing measure. This is RTL
activity applied to a new synthesis, with no placed/routed parasitics or claimed
SRAM internal activity. It produces no official score or physical signoff.

Local tests require no PDK or DC license:

```bash
python3 -m unittest discover -s tests -p test_power_server.py -v
```

The Tcl tests use an embedded Tcl interpreter (`tkinter.Tcl`) when available;
they verify command ordering, all twelve task resets, unsupported-command
failure, and annotation failure. They do not establish real server results.

The upload must include top-level `run_power.sh`, `tools/power_server.py`,
`tools/ppa_metrics.py`, and `script/power_run.tcl`, plus `power_study` and all
selected case synthesis sources/config/scripts. Server execution imports only
`ppa_metrics.py` and the Python standard library; it does not require the local
capture/export tools or `tkinter`. Case-local synthesis scripts source their
own existing dependencies. No PDK data or local tool configuration is bundled.
