## 硬件与资源

`integration/kwt_encoder_soc.sv` 是新整机顶层。新增 `kwt_extended_system_bus`，保留原三方总线，在 DMA 端增加两路轮转仲裁，记录已接收请求的响应归属；阻塞请求保持到接受，最后写响应返回后才完成。

`rtl/kwt_encoder.sv` 是注意力/归一化伴随引擎，四路共享 32×32 乘法器、72 位累加器，服务投影、QK、PV、方差和仿射操作；Softmax 使用固定数学常数的查表线性插值，LayerNorm 使用迭代整数平方根和倒数除法。四路共享乘法器之外，指数插值和既有 GELU 还有辅助算术，不把“20 个 MAC”误称为整个 SoC 仅有 20 个乘法运算符。

内部 SRAM 使用原来的无复位、同步单端口 16 位宏边界：

| 内容 | 容量 |
| --- | ---: |
| 原 FFN | 88.5 KiB |
| 新 X/Q/K/V，四个向量缓存 | 128 KiB |
| 复用的一组投影权重 | 16 KiB |
| 输出偏置和两组 LN 参数 | 2 KiB |
| 单行分数/概率复用缓存 | 0.5 KiB |
| 加速器内部总计 | **235 KiB / 240,640 B** |

第二版综合保留 **122 个内部宏**：2×16×4096、108×16×1024、12×16×128，第三版 RTL 宏组织不变。新增 FIFO 使用 20 B 负载寄存器及控制寄存器，另有打包寄存器。512 KiB System Bus 共享 SRAM 和 E203 自有存储边界单独统计，不在上表内；不能据宏字节数推断满足物理面积限制。

每次只保留一行 99 个注意力分数/概率。查询行完成后，其 Q 缓存位置覆写为 PV 输出；K/V 仍保留用于后续行。投影权重缓存被 Q、K、V、O 依次复用。LN2 结果保留为下一层 X，可省掉中间 11 层的输出写回和再次读取。FFN 输入仍经共享 SRAM，输出默认经 4×40 位 FIFO 直接送至编码器 tail；旧64位和紧凑40位 SRAM 交接保留。

## 第四版输出合并调度

FIFO 观测表明满等待为零、最大占用3/4，瓶颈主要在 FFN 供给。输出组将40位奇偶部分和直接写入现有 FIFO，省掉独立 MERGE 拍；进入 GELU 前仍保留合并寄存器。每层 FFN 和并发 tail 各减少792拍，两者不能重复相加。独立线性层为167,134周期，完整 FFN 为305,708周期，完整编码器为14,549,345周期。接口与数学运算顺序不变；计数来自仿真观察器，无新增硬件寄存器。详细拆分见 [FIFO研究](fifo-study.md)。

## 第三版计算与传输（保留实现）

独立第一线性层也启用现有 16 路 MAC，奇偶 k 同时读取、分别累加，再合并 40 位结果。FFN DMA 使用两笔顺序在途请求及同拍结果补入，独立线性层降至 170,236 周期，完整 FFN 为 306,703 周期。

packed40 每 4 个有符号40位结果打成 5 个32位字，FIFO40 使用带背压的直接链路。两者只删除64位存储中的冗余符号位，接收端仍按原顺序进行符号扩展、缩放舍入、加 Z、饱和和 LN2。FIFO 模式必须并行启动 FFN 与 tail，并等待两端完成；错误/中止清空队列并停止对端。详细协议、计时和验证见 [前端传输优化](frontend-transfer.md)。

## 第二版前端调度与 DMA（保留实现）

第二版优化调度：Q/K/V 保存结果时预读下一组 X/权重并清累加器；QK 保存分数时预读下一 key；PV 保存当前组时预读下一组概率/V；输出投影保存阶段预取下一组偏置，残差写回时预取其首项。第三版保留这些优化和数值顺序，并修改 FFN 调度与结果交接。

编码器 DMA 使用独立发出与接收游标、两笔顺序在途信用。正常运行可同拍接受下一请求与处理上一响应；输入/参数按整段连续读取，输出按整段连续写回。写回预取复用 `norm_value`，紧凑 int16 打包支持同拍旁路。FFN 输出每 8 个 32 位字连续读取，组间仍需残差向量 SRAM 的读取和保存拍。单端口 SRAM 约束不变，不新增 SRAM 宏。

总线必须按请求顺序返回响应，且响应至少延后一拍；现有 System Bus 符合此约定。中止或响应错误锁存停止状态，保持已经受阻的请求，排空全部已接受请求后才退出 busy。最后一次写响应确认之前不置 done。已有错误状态并不撤销此前被接受的写事务。

## 数值契约

`model/encoder-format.json` 冻结 Q16 激活和注意力/LN 参数、Q24 概率。格式来自固定数学选择，不使用验证集调整尺度。FFN 继续使用 `format.json` 和 `ffn-format.json`。

- 投影与 QK 使用宽整数精确累加、最近偶数舍入和有符号 int32 饱和；QK 右移 19 位同时实现 Q32→Q16 与除以 8。
- Softmax 先减行最大值，`log2(e)` Q16=94548，257 项 Q24 `2^(-i/256)` 表配合线性插值；差值 ≥16 时指数为零；行倒数为 `floor(2^48/sum)`，概率采用下取整。
- LayerNorm 对每行 64 个特征归一化；均值、总体方差取整，epsilon=4295×2^-32 对应原模型 1e-6；使用整数 `isqrt` 和 `floor(2^36/std)`。中心化、残差、仿射结果饱和到 int32。
- LN1→FFN 输入按原指数最近偶数舍入并饱和 int16；FFN int64 输出按该层输出指数舍入到 Q16 后与 Z 相加。训练和验证中均不再拟合参数。
- 饱和计数统计注意力/残差/中心化/仿射/FFN 输入压缩的实际裁剪事件；中心化每个元素只在方差阶段计一次。原 FFN 的 GELU 饱和是单独计数。

本地 120 条固定验证样本：浮点和整数分类均 **119/120**，预测一致 **120/120**；最大逐层聚合 NRMSE 为 **0.171713%**。24 条训练检查样本均正确。这里的 NRMSE 是逐层聚合值，不是单样本最大值；本地准确率不是官方 600 条评测成绩。

后续保持格式与原整数算术文件不变，将软件验证扩大到完整上游 validation 索引 **4,445 条**（4,074 个不同音频 + 371 个重复静音条目）：浮点与整数均正确 **4,351/4,445（97.8853%）**，预测全部一致，所有监测阶段实际饱和次数为 **0**。最大逐层聚合 NRMSE **0.171308%**，最差单样本逐层 NRMSE **0.237820%**。原 120 条复测与历史数值完全一致；这次扩展不增加 RTL 整机仿真条数。逐层误差、分类明细、饱和和复现方式见 [扩展验证报告](encoder-validation-expanded.md)。

参考使用固定上游 KWT-1 `best_weights`，导出前逐项核验 162 个 checkpoint 张量；本机仍采用已有 TensorFlow 2.4.0 开发环境，尚未被官方认证为其原始 2.4.0rc1 运行环境的完全等价替代。官方环境到位后需按同一冻结格式复核。

## 操作与寄存器

旧 KWT5 基址 `0x40000000`、模式 0=FFN1、1=完整 FFN 不变；新增模式2=完整 FFN 紧凑40位写回、3=完整 FFN FIFO直传，`0x94` 统计已被接收的直传结果数。ENC1 基址 `0x40080000`，ID=`0x454e4331`。同一推理的 front/tail 必须按顺序执行，不能在中间启动另一个推理覆盖驻留数据。直传要求两个实例启用 `STREAM_ENABLE` 并连接 FIFO。

| 偏移 | 含义 |
| --- | --- |
| 0x00 | 写 1 启动；2 请求中止并排空事务；4 在空闲时使驻留状态失效并清状态 |
| 0x04 | bit0 busy，1 done，2 DMA/算术错误，3 aborted，4 config error，5 resident_valid，6 z_valid |
| 0x0c | ENC1 ID |
| 0x20 / 0x24 | X / 注意力和 LN 参数基址 |
| 0x28 / 0x2c / 0x30 | 紧凑 FFN 输入 / FFN 结果缓冲区 / 编码器 Q16 输出基址 |
| 0x34 | bit0 front 复用驻留 X；bit1 tail 不写回；bit2 packed40；bit3 FIFO40；bits12:8 FFN 输入右移；bits20:16 FFN 输出右移；其余位必须为零，bit2/3 互斥 |
| 0x38 | 0=front：注意力→残差→LN1→FFN 输入；1=tail：读 FFN 输出→残差→LN2 |
| 0x40 / 0x44 | 本命令总周期 / 乘法活动周期 |
| 0x48 / 0x4c | 已接受 DMA 读 / 写命令，单位 32 位字 |
| 0x50 / 0x54 | 本引擎内部 SRAM 读 / 写访问，单位 16 位宏访问 |
| 0x58 / 0x5c | 饱和次数 / 状态及除法、平方根忙标志 |
| 0x60 / 0x64 / 0x68 / 0x6c | QKV / QK / Softmax / PV 阶段周期 |
| 0x70 / 0x74 / 0x78 | 输出投影及残差1 / LN1 / LN2 阶段周期 |
| 0x7c / 0x80 / 0x84 | 输入与参数 DMA / FFN 结果 DMA 及残差2 / 输出 DMA 阶段周期 |
| 0x88 | DMA 请求有效但未被接受的周期 |
| 0x8c | 有在途请求但无返回响应的周期 |
| 0x90 | 同拍接受请求与退休响应的周期 |

新增计数器均为 32 位，只读，每次成功启动清零。0x60—0x84 十项互斥，包含阶段控制拍，求和等于 0x40；0x88—0x90 是已包含于阶段周期中的重叠诊断，不能累加至总周期。FIFO 下 0x80 包含等待生产者的时间，FFN 与 tail 并行，不能再相加。推荐在 busy=0 后读取稳定快照。第三版使用同一个新固件二进制比较三种传输方式，历史第二版固件仅作历史对照。

不允许未完成 front 就执行 tail，也不允许无有效驻留数据时请求复用。中止和复位都使驻留状态失效；中止保留阻塞的已发出请求，直到被接受并得到响应。地址对齐、共享 SRAM 范围、关键缓冲区重叠和保留位检查在启动前执行。运行时配置写被拒绝。数据 SRAM 不复位，完整装载与状态有效位防止读取旧任务内容。

每层参数区连续 16,704 个 uint32：wq/wk/wv/wo 各 4096 字，随后 bo/g1/beta1/g2/beta2 各 64 字；矩阵按四个输出列成组、k 在组内连续排列。FFN W1/W2 每字两个 int16，低半字是先出现元素。

共享内存布局（全部位于 512 KiB 窗口内）：

| 地址 | 内容 | 字节 |
| --- | --- | ---: |
| 0xa0010000 | 初始 X Q16 | 25,344 |
| 0xa0018000 | FFN 输入 int16 紧凑数据 | 12,672 |
| 0xa0020000 / 0xa0028000 | W1 / b1 | 32,768 / 1,024 |
| 0xa0030000 | FFN 结果：64位 / packed40 / FIFO | 50,688 / 31,680 / 不传输 |
| 0xa0040000 / 0xa0048000 | W2 / b2 | 32,768 / 256 |
| 0xa0050000 | 注意力/LN 参数 | 66,816 |
| 0xa0064000 | 最终编码器 Q16 输出 | 25,344 |

`firmware/kwt_encoder_driver.c` 先执行 front。旧64位与 packed40 模式完成 FFN 写回后再执行 tail；FIFO 模式启动 FFN 后立即启动 tail，最终检查两端完成。任一端失败则停止两端。CPU 仅控制、搬运描述和读取计数器，不计算模型算子。每层需从加载端更新 33,408 个 32 位参数字。十二层全部权重不要求同时驻留在共享 SRAM 中。

## 验证与复现

先完成 README 中的资源和环境配置，保留原 `design.ps1` 回归。新入口：

```powershell
.\encoder.ps1 all
```

依次完成冻结模型导出、独立算术检查、组件中间矩阵核对、Icarus 四态仿真、总线/异常测试、旧模式兼容回归、12 条输入各运行 12 层的真实 E203 RTL、同配置 A/B、通用综合、1 条输入全部 12 层的网表整机回归、两种旧模式各 12 个网表任务、汇总和打包。整机和四态回归较慢，日志持续写入 `output/design/`。

单独运行例如 `python scripts/run_encoder.py soc --tasks 12 --jobs 4`（四个独立仿真进程各执行三条输入，汇总前逐个检查完整通过；并行仅缩短宿主机运行时间，不改变硬件周期）、`python scripts/run_encoder.py netlist --tasks 1`。网表验证不含单元延时和工艺 SRAM 时序，属于逻辑功能验证。组件测试覆盖原单笔背压总线、理想连续总线、两笔在途延迟响应总线，并检查地址/数据保持；理想模式要求读取和写回连续 6,336 字。组件测试的 tail 使用参考 FFN 结果向量；整机测试中间调用的是实际 FFN RTL/网表，二者证据边界不同。

SoC 计时包含初始输入加载、12 次参数加载、CPU 命令与统计、两个硬件引擎执行以及最终写响应和通知观察。固件初次装载、测试前清哨兵和计时结束后的逐字比较不计入。跨层复用 A/B 使用同一二进制、同一输入、同一参数和软件，仅改变复用/写回标志；不能用较小的 FFN 任务直接计算完整编码器的“加速比”。

官方清单到位后，使用冻结格式评估，不回调尺度：

```powershell
.venv-model\Scripts\python.exe scripts/export_encoder.py --split testing --sample-list official-samples.json --output output/encoder-official
```

JSON 清单为数据集相对音频路径数组，静音写 `"silence"`。脚本检查数据划分，执行全清单分类比较并为前 12 条输出硬件向量。官方平台仍需用对应加载/读取接口执行硬件评测；此命令本身不构成官方验收。
