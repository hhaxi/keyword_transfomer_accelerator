## 修改及其作用

1. 权重按相邻列交错分布到原有四个 SRAM bank，四路 MAC 共享 X，每组并行计算四个输出，不增加 SRAM 容量。
2. 同步读取与上一拍操作数的乘加重叠，预取/排空明确分离，64 项内积不漏项、不重复。
3. 两组深度的输出 FIFO 将 MAC 与 CPU 消费分开。满载时保持结果，读高半字时弹出，允许入队和出队同拍发生。
4. 驱动按四个结果检查一次就绪，并展开输入装载和输出写回循环，减少 E203 轮询和循环开销。

第一版每个标量输出需 2 周期偏置读取和 128 周期读取/MAC，随后停机等待取走。第二版无输出背压时 74 周期产生四个结果，共 6,336 组，即 468,864 个计算调度周期。这是理想的内部调度预算，未包含装载、CPU 搬运、背压和最后结果排空；不能用它作为整任务耗时。整机收益小于内部计算收益，后续进一步提速应优先分析 CPU 数据搬运和写回路径，再决定是否增加计算并行度。

## 验证与复现

- 保留全部 12 组实际参数逐位检查，分别覆盖加速器 RTL、真实 E203 RTL、加速器通用网表和 E203 通用网表；每条路径检查 304,128 个输出。
- 加速器测试增加 FIFO 长时间满载、重复读取低半字、周期性停止消费、逐结果/四结果混合访问、带待取结果的中止和复位。
- Icarus 四态仿真验证一组完整矩阵，MAC 极值/符号/保持/复位测试继续保留。
- 数值格式、模型权重、参考向量和运算顺序未改，120 样本逐层最大 NRMSE 仍为 0.013202%；官方 600 样本待评。

`performance-baseline.json` 保存第一版周期及校验值，`performance-comparison.json` 由实测日志生成。比较脚本验证测试平台、总线、数值合同和向量清单未变、综合前后周期一致，并检查本地固定负载的整机加速至少达到 2 倍。加速器独立测试增加了更强的背压，因此不以其新旧总周期作为严格的整机加速比。

第一版活动文件已归档到本地 `output/baseline-v1/`，不复用为第二版功耗证据。本轮未重新采集完整 SoC 活动波形；官方功耗分析前须用第二版代码和同一固件重新采集并检查覆盖。
