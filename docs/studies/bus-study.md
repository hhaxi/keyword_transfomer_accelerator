# 共享总线停顿归因与有界 DMA 仲裁（c0724ce）

基于 `c0724ce0150b0b9441659f3e2b1c69c064293c85`。本轮新增可关闭的仿真观测，覆盖扩展 E203 SoC 上的独立 Linear、完整 FFN 和十二层编码器；根据实测增加一个可选的 **8 笔 DMA 加权轮转**。默认 `DMA_BURST=1` 保留原行为，`DMA_BURST=8` 用于对照。没有修改运算、数值格式、SRAM 宏或固件轮询逻辑。

主要结论：正常任务中**响应槽阻塞为0**，既有的同拍返回/接纳已经工作；DMA 请求停顿主要来自 CPU 取指竞争。将有限的仲裁份额移给 DMA 能缩短关键装载及 FFN 等参数时间，但也增加 CPU/主机的最长等待。总等待次数不是任务周期，应以完整任务和其他主设备进度共同判断。

## 1. 观测方法

编译开关 `BUS_STUDY` 加入 `tests/bus_study_monitor.svh`；运行参数 `+bus_stats=0` 关闭观测，默认开启。观测器不驱动或强制 DUT 信号。原始 `c0724ce` 的三种模式均运行观测开/关对照，完整任务周期完全相同。

CPU 取指使用固定版本 E203 的 `u_e203_biu.buf_icb_cmd_ifu` 来源标记，并断言它的 valid/address 与 SoC 对外命令一致。分类如下：

| source | 来源 | 口径 |
| --- | --- | --- |
| 0 | CPU 取指 | BIU 来源标记为 IFU，按真实来源识别 |
| 1 | CPU 加速器状态轮询 | LSU 读 `0x40000004` 或 `0x40080004` |
| 2 | CPU 其他 | 其他 LSU 访问，包含邮箱轮询、配置、栈和统计读写 |
| 3 | 主机 | 外部加载器及完成邮箱轮询 |
| 4 / 5 | FFN DMA | 读 / 写请求 |
| 6 / 7 | 编码器 DMA | 读 / 写请求 |

每个有效请求每拍只进入以下一个桶，按列出的顺序归因：

| cause | 分类条件 |
| --- | --- |
| `accepted` | 当拍握手成功 |
| `slot_target` | fabric 上一响应未完成，目标尚未返回 valid |
| `slot_sink` | fabric 上一响应已有 valid，接收方尚未 ready |
| `dma_slot` | fabric 可接纳，但 DMA 子仲裁器上一响应尚未释放 |
| `dma_peer` | fabric 可接纳，当前 DMA 请求在子仲裁器输给另一个 DMA |
| `grant_ifu/poll/cpu/host/ffn/enc` | 当前请求在外层仲裁中输给对应来源 |
| `target` | 已获外层仲裁，但目标命令端尚未 ready |
| `other` | 未归因，仿真直接失败 |

响应槽另按其**原请求来源**统计“等待目标返回 / 等待接收方 / 当拍返回”，并加上空槽，逐拍闭合到任务周期。槽占用不等于阻塞：上一响应本拍可返回时，下一个请求可以同拍接纳。

请求桶在同一来源内互斥，不同主设备可能同拍等待，不能跨来源相加当作全局周期。日志还记录全局等待并集、串行 DMA 窗口等待并集、各来源最长连续请求等待。编码器 DMA 细分为 X、公共参数、Q/K/V/O 权重、输出和尾段；FFN 细分为初始/预装载、计算期间读以及写回。FFN 输入直传模式的提前权重装载虽处于 LOAD 状态，也不能当成串行关键路径。

计数窗口与原测试任务计时完全一致，包含主机输入/权重加载、CPU 控制、加速器运行、最后写回及完成通知观察，排除初次固件加载和计时后的结果核对。窗口边缘可有在途 CPU 请求，所以接纳数与返回数不强制相等；最长等待仅统计窗口内部分。所有 DMA 请求均位于任务窗口中。

## 2. 原始基线的停顿来源

task 0，三种模式使用相同的真实单端口共享 SRAM 和原轮转仲裁。表中为 DMA 请求等待事件；编码器行包含两个 DMA，因此是请求事件总数。

| 工作负载 | 被 CPU 取指挡住 | 被加速器状态轮询挡住 | CPU其他 | 主机 | DMA同伴 | DMA等待总数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Linear | 18,427 | 1,421 | 0 | 156 | 0 | **20,004** |
| 完整 FFN | 9,774 | 827 | 0 | 52 | 0 | **10,653** |
| 十二层编码器 | 125,475 | 12,527 | 24 | 544 | 12 | **138,582** |

以上三种模式中，`slot_target`、`slot_sink`、`dma_slot`、`target`、`other` 均为 **0**。这不代表总线空闲：响应持续占用槽并正常返回，且存在大量同拍返回/接纳。增加响应队列或再做“返回与请求重叠”没有当前工作负载的直接收益证据。

| 基线响应槽 | 占用周期（均可正常返回） | 空槽周期 | 同拍返回并接纳下一请求 |
| --- | ---: | ---: | ---: |
| Linear | 115,146 | 51,988 | 93,876 |
| FFN | 129,079 | 176,629 | 63,343 |
| 十二层编码器 | 4,410,984 | 9,904,135 | 967,234 |

前两列之和等于完整任务周期；最后一列与占用列重叠。

主机自身等待分别为 **11,773 / 20,001 / 407,775 拍**，大部分来自 CPU 竞争。这里包括任务内数据加载和邮箱完成轮询，不全是可直接删除的串行开销；本轮未修改主机优先级，也未把该预算算入 DMA 改动收益。

结合测试端明确串行的数据写入数 **11,616 / 19,872 / 407,232** 和基线主机最长等待1拍，可给出主机数据加载等待区间 **[11,538, 11,773] / [19,560, 20,001] / [395,375, 407,775]** 拍。下界用“全部主机等待 − 非数据请求数×最长等待”得到，上界为全部主机等待；它避免把邮箱轮询等待全部当成加载开销。这是下一轮可优先验证的机会，本轮只实施DMA仲裁这一项。

## 3. 关键路径与收益预算

| 窗口 | 观察到的等待 | 对关键路径的判断 |
| --- | ---: | --- |
| Linear 初始输入/权重装载 | 3,912 | 在计算启动前，明确暴露；写回等待16,092拍主要与计算交叠 |
| FFN 初始装载 | 3,912 | 在计算启动前；后续读等待2,781拍及写等待3,960拍不能全部直接相加 |
| 十二层编码器自身读/最终写 | 71,418 | 处在编码器串行 DMA 窗口，约占任务0.499%；含12拍让出给既有FFN请求 |
| 十二层 FFN 权重预装载 | 67,164 | 大部分在注意力计算期间隐藏；缩短它不等于提前FFN输入就绪 |

在固定请求序列及计算调度下，删除所观测 DMA 停顿的**极乐观预算**分别为 **20,004 / 10,653 / 138,582 拍**，约为完整任务的 **11.97% / 3.48% / 0.97%**。这是允许重复覆盖并行窗口的宽松上界，不能作为预计加速；严格串行部分远小于这些数。十二层编码器自身的71,418拍预算约为0.499%，FFN提前装载那部分应先检查是否仍赶得上LN1输出。

单纯优化响应槽等待，本次样本的可删除预算为 **0**。CPU/主机争用优化还有其他候选窗口，但调整这些访问会影响CPU指令进度、轮询次数和任务完成的采样相位，不能把它们与上述预算直接相加，也不能把等待预算解释为严格的整机周期承诺。

8笔对照进一步给出因果证据：

- Linear 初始装载请求等待 **3,912 → 1,476**；硬件装载阶段 **15,529 → 13,093**。全部 DMA 等待 **20,004 → 4,711**，但完整任务只减少2,131拍，说明多数写回等待本来可以隐藏。
- FFN 初始装载阶段同样 **15,529 → 13,093**。第二层参数等待 **2,563 → 832**，GELU重叠计数仍为25,240，MAC计数仍为202,752。完整任务收益同时来自启动前装载和运行中参数就绪，并非所有搬运均已完全隐藏。
- 编码器每层 QKV 的308,886拍及其他纯计算阶段保持原值，变化发生在搬运和控制交接。FFN预装载命令与注意力有重叠，不能把两者命令周期缩短相加。

## 4. 唯一硬件改动：有界 DMA 轮转

`kwt_bus_fabric` 新增 `DMA_BURST` 参数。值为1时与原仲裁行为一致；值为8时，DMA轮次内最多接纳8笔请求，再按原顺序检查CPU和主机。

计数的是**成功接纳的请求**，不是时钟。没有请求时不阻止其他主设备，发生目标反压时仍锁定既有授予，响应阻塞仍保持原响应及数据；复位清零轮次计数。两个加速器之间的子仲裁器保持原公平规则。8笔模式增加一个3位轮次计数器，不增加 MAC、SRAM 或响应缓冲；资源和时序影响尚未综合测量。

配置通过 `kwt_encoder_soc` → `kwt_extended_system_bus` → `kwt_bus_fabric` 传递：

```systemverilog
kwt_encoder_soc #(.DMA_BURST(8)) system_instance (...);
// DMA_BURST=1 为默认基线；当前正式验证的参数为1和8。
```

试验脚本使用编译开关 `BUS_BURST8` 在测试顶层选择8，普通脚本继续使用默认1。它是编译/展开时的参数对照，不是新增运行时寄存器。两份二进制的固件、向量、时钟、主机行为和检查逻辑保持一致。

## 5. 完整任务对照与等待代价

| 工作负载 | 参数1 | 参数8 | 减少 |
| --- | ---: | ---: | ---: |
| 独立 Linear | 167,134 | 165,003 | 2,131（1.2750%） |
| 独立完整 FFN | 305,708 | 301,408 | 4,300（1.4066%） |
| 单层编码器 | 1,231,235 | 1,225,034 | 6,201（0.5036%） |
| 十二层编码器 | 14,315,119 | 14,263,416 | 51,703（0.3612%） |

必须区分硬件命令窗口和完整任务：Linear硬件命令减少 **2,440** 拍，完整任务减少 **2,131** 拍；FFN分别减少 **4,171 / 4,300** 拍；十二层编码器前段与尾段命令合计减少 **44,549** 拍，完整任务减少 **51,703** 拍。相应的其他任务时间变化为 **−309 / +129 / +7,154** 拍（正数表示节省），包括外部加载、CPU交接和完成轮询。十二层硬件窗口的减少与串行DMA等待减少量一致。编码器每层完成通知采用1,024拍轮询，不能把整机差额全称为硬件搬运提速。

两种参数各执行独立Linear 12个任务、FFN 12个任务，十二层编码器各执行task 0一条输入；编码器单层试验通过后才运行参数8的十二层。三种模式的加速器DMA流量保持 **62,304 / 32,544 / 413,568 个32位字**；单层编码器保持46,080字。CPU执行的轮询次数、取指数量及主机邮箱检查次数可随任务时长变化，不强求其请求数量相同。

正常工作负载中，默认CPU取指/状态轮询/主机最长等待通常为0—1拍，8笔模式可到8拍；逐来源、逐任务实测值见机器报告。对持续三主设备竞争有更强的受限保证：

| 压力场景 | 参数1 CPU/主机/DMA | 参数8 CPU/主机/DMA |
| --- | --- | --- |
| 无目标/响应停顿：最长请求等待 | 2 / 2 / 2 拍 | 9 / 9 / 2 拍 |
| 加入周期性响应背压：实测最长等待 | 16 / 12 / 16 拍 | 18 / 21 / 10 拍 |
| 持续有效请求被其他已接纳请求越过的上界 | 2 / 2 / 2 笔 | 9 / 9 / 2 笔 |

上述不是任意外部反压下的绝对时钟上界：若目标永不ready或接收方永不接受响应，等待可无限延长。公平保证针对可继续接纳请求的轮次；有背压时仍保持响应和锁定请求稳定。Verilator与Icarus对压力场景得出一致计数。

## 6. 正确性、恢复与复现

- 保留冻结整数模型和六份数值契约 SHA-256。未修改RTL算术、格式、固件、向量或乘法器数量。
- 两参数下，独立Linear各检查12×25,344个结果，FFN各检查12×6,336个结果，逐位匹配冻结向量。
- 编码器逐层检查Q/K/V合计228,096个int32、LN1输入38,016个打包字、FFN输出76,032个int40以及最终6,336个结果，饱和计数为0。
- 两参数下，实际双DMA/FIFO链路覆盖权重装载中取消、输入部分接收后取消、前段空闲但FIFO未排空时取消；覆盖双向传播、排空、清除、再启动及逐位输出。
- 总线测试覆盖连续吞吐、三主设备公平性、响应背压、锁定请求、地址保护错误和待响应时复位。两参数通过Verilator与Icarus；扩展系统两参数均通过严格RTL lint。
- 没有新做综合、网表、面积、功耗或时序测量，不把仿真周期收益表述为PPA改善。
