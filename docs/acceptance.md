## 本地结果

- 数值验证使用原始 checkpoint 的 162 个模型张量，逐项核验后提取第一处 PostNorm 后的 FFN 输入。没有训练、微调或测试集调参。
- 从训练划分选择 24 条样本检查解析尺度的动态范围与饱和情况，配置保持冻结；此记录与验证集结果分开保存。
- 120 条样本按指定源码划分和标签规则选自验证集，均衡覆盖十二类；总计比较 36,495,360 个浮点输出。详细样本和每层结果见 `numeric-validation.json`。
- 12 个 RTL 性能任务的单任务最大 NRMSE 约 **0.013344%**；此项与 120 样本逐层聚合的最大值分别记录，不混用。
- 第三版完整 SoC 每任务 **592,266 周期**；按 150 MHz 目标折算为 **3.94844 ms/任务、253.26458 任务/秒**。相比第二版 2,298,840 周期降低 74.24%。这是频率目标下的折算值，不能代替实际时序达标证明。比较口径、分阶段周期和资源代价见 [DMA 与周期分析](dma-performance.md)。
- 仿真时钟周期为 6.666 ns（1 ps 时间精度）；周期统计为整数，吞吐统一按 150 MHz 计算。正式活动功耗分析需按官方精确时钟条件重新采集/归一化。
- 软件 TensorFlow 2.4.0 是已记录的开发替代版本，与指南原始 2.4.0rc1/官方浮点环境的等价性仍需最终核对。

机器可读记录为 `design-validation.json`、`cycle-analysis.json` 和 `performance-comparison.json`，包含日志和源文件校验值；完整日志、MAC 波形、固件和网表在本地 `output/design/`。第一版整机活动文件保存在 `output/baseline-v1/`，第三版当前没有整机活动文件，不可混用于功耗评估。

## 可复现交付

1. 按 README 下载固定资源并配置环境。
2. 运行 `.\design.ps1 all`；此命令会重新生成真实向量，不依赖缓存答案。
3. 按需运行活动采集命令，然后运行 `python scripts/collect_results.py` 更新记录。
4. `output/design/kwt_accel_netlist.v` 为计算核，`kwt_dma_netlist.v` 为包含计算核的 DMA 引擎，`kwt_bus_netlist.v` 为三方总线，`kwt_soc_netlist.v` 为 E203 集成通用网表。层级有包含关系，面积不能重复相加；SRAM 保留为工艺边界，需要配套功能模型仿真。
5. 官方评测集发布后，用冻结 `model/format.json` 和 `evaluate_numeric.py` 按层汇总 600 条样本，不能修改数值格式后继续称同一冻结提交。

## 官方资料到位后的完成条件

需要官方标准单元 Liberty、工艺角、SRAM 功能/时序/功耗模型及宏面积、统一负载/互连估计条件和最终平台工程。取得这些资料后，替换宏边界、接入平台地址与参数加载接口，在同一配置/网表上完成时序、面积、活动覆盖、平均功耗和能耗评估。指标不满足时须修改设计并重新执行相关验证。

当前报告中未知的物理指标使用 `null` 或“未验证”，不会把 SRAM 黑盒当作零面积/零功耗，也不会伪造时序裕量。
