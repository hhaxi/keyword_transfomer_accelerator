# 第四版：8 路 MAC、偏置预取与紧凑传输

本页保留第四版必做基线结果。当前第五版完整 FFN 与独立模式见 [完整 FFN 报告](full-ffn.md)；当前命令运行第五版，复现第四版请使用下述固定提交或历史归档。

第四版完成方案 B 加紧凑打包。12 个真实层任务在 E203 RTL 和通用综合网表上均为 **271,678 周期/任务**，比第三版加速 **2.1800 倍**，周期减少 **54.13%**。全部 304,128 个输出逐位一致，15 项周期统计综合前后相同。

## 周期来源

以下互斥阶段可以相加；12 个任务的分解均相同。

| 阶段 | 第三版 | 第四版 | 变化原因 |
| --- | ---: | ---: | --- |
| 外部装载及就绪通知 | 91,907 | 46,467 | X/W 两个 16 位元素合为一个 32 位字 |
| DMA 加载 | 30,717 | 15,530 | 同一响应同时写入奇偶两个 SRAM bank |
| 计算与结果写回 | 468,879 | 209,135 | 8 路并行、隐藏后续组的偏置读取 |
| DMA 控制转换 | 2 | 2 | 清空与启动 |
| CPU 配置和完成观察余量 | 761 | 544 | 固件调度及轮询采样位置 |
| **总计** | **592,266** | **271,678** | |

DMA 内部总耗时为 `224,667 = 15,530 + 209,135 + 2` 周期。第四版每组产生八个输出，共 3,168 组：首组偏置读取 16 周期，之后每组为 1 周期初始化/首项预取、64 周期 MAC、1 周期入队。无背压调度预算为 `16 + 3,168 × 66 = 209,104`，最后一组结果排空和写响应构成剩余尾部开销。

诊断计数：MAC 有效 202,752 周期，每拍八路工作；核心耗时 209,130 周期；FIFO 满等待为 0；DMA 请求等待 24,466 周期；响应等待为 0。首个输出时间戳 15,615，最后输出 224,662，最后写响应 224,667。这些统计有重叠，不能加到上述互斥阶段之上。

## 硬件与传输格式

- 同一个 X 元素广播到八路有符号 16×16 MAC，累加仍为 40 位，k 的运算次序保持 0 到 63。冻结的数值格式、权重、输入与参考输出均未变化。
- 初始读取八个偏置；当前组运算前 16 拍预取下一组的八个偏置，包括跨行回到第 0 组的情况。256 位预取寄存器在下一组 PRIME 时初始化八个累加器。
- 输出 FIFO 扩为 16×40 位，两组容量，每次入队八项。背压时保留结果；错误、中止及复位清除有效状态，后续任务重新装载。
- X 按元素奇偶分布在两个 `16×4096` 单端口 SRAM；W 按输出列模 8 及 k 的奇偶分为十六个 `16×1024` 单端口 SRAM；b 使用两个 `16×1024` 单端口 SRAM。总容量仍为 53,248 字节。未增加共享 SRAM 容量、端口或降低它的同步读延迟。

第四版 DMA 控制器 ID 为 **KWT4 / `0x4b575434`**，寄存器偏移保持第三版布局；旧 KWT3 驱动必须更新。X/W 每个 32 位传输字的低半字是先出现的元素，高半字是后一个元素，采用小端字节序。例如 `[-32768,32767]` 编码成 `0x7fff8000`，`[-1,0]` 编码成 `0x0000ffff`。X 仍行优先，W 仍列优先，b 保留 32 位，Y 保留 64 位符号扩展。

X 为 3,168 字（12,672 字节），W 为 8,192 字（32,768 字节），b 为 256 字（1,024 字节），总装载量从 91,904 降为 46,464 字节，减少 49.44%。本地地址仍为 X=`0xa0010000`、W=`0xa0018000`、b=`0xa0028000`、Y=`0xa0030000`。完整地址范围、4 字节对齐、与输出重叠及地址回绕检查已按实际紧凑长度更新。

`x.hex/w.hex` 作为原始逐元素向量保留，实际 SoC 加载新增的 `x_packed.hex/w_packed.hex`。导出、任意输入转换和独立 `pack_vectors.py` 都支持生成紧凑文件。原 `manifest.json` 保留其数值向量合同，`packed-manifest.json` 单独记录源文件、紧凑文件哈希及字数。打包不做数值运算，不预先计算硬件答案。

独立核心原 MMIO 仍支持每字一个元素，供组件回归使用；DMA 流接口改为每字两个 X/W 元素。完整接口定义见 [架构说明](architecture.md)。

## 同条件比较与验证

第三版基线为提交 `e85a6899ac7c363ecf9dcce3809bfeaa80ccd41d`，记录在 `docs/history/performance-baseline-v3.json`；本地历史日志在 `output/baseline-v3/`。

`compare_performance.py` 检查原始向量和冻结格式未变，紧凑字可无损还原，并验证共享 SRAM、CPU 连接及总线源码未变。测试平台只允许新增紧凑数组/一致性检查、替换 X/W 装载字数及对应活动计数断言；将这些指定差异还原后必须与第三版测试平台哈希一致。主机握手、时钟、计时起止、任务前复位、轮询和最终输出检查都保持原样。所有实际装载事务仍在计时内，统计快照仍在计时外。

已通过：

- 核心 RTL/网表和真实 E203 SoC RTL/网表各 12 个任务，每条路径检查 304,128 个输出；综合前后周期一致，SoC 的 15 项统计也一致。
- DMA RTL、综合网表及 Icarus 四态：读/首写/末写错误、延迟响应、请求背压、忙时非法配置、中止、读写期间复位、故障后恢复、最后写响应前不能 done。
- 新增紧凑地址长度的上界检查、越界一字拒绝、32 位地址回绕拒绝；最后合法 X/W 基址可启动。
- DMA 压力测试三条路径统计相同：总周期 250,143，加载 40,644，计算/写回 209,497，控制 2，FIFO 等待 303；故意阻塞下确实产生背压。
- 传输单元测试遍历全部 65,536 个 int16 值，检查半字顺序、符号、无损往返及非法截断拒绝；12 组真实向量全部核对。
- 数值模型边界测试、100 组 MAC 测试、核心四态检查和总线连续吞吐/仲裁检查通过；自有系统 RTL 严格 Verilator `-Wall` lint 无警告。

数值模型和原始向量保持冻结，沿用已验证的 120 条验证样本 × 12 层结果，逐层聚合最大 NRMSE 约 **0.013202%**。本轮没有重新调量化参数，尚未执行官方 600 条样本评测。

## 复现

```powershell
python scripts/pack_vectors.py
.\design.ps1 numeric
.\design.ps1 accel
.\design.ps1 dma

.\design.ps1 synth
```
