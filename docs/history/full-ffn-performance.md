# 第六版：完整 FFN 双项并行优化

> 本文保留第六版 `411a151` 的历史结果。当前第八版见 [组间调度优化](../ffn-group-scheduling.md)。

第六版保持完整 FFN 的输入、权重、冻结量化配置、GELU 数学表、输出格式和 KWT5 协议不变。完整模式在八个输出通道内各并行处理两个相邻 k 项，独立第一层继续使用原来的单项路径。

第五版基线提交为 `aa344f96043682ecf8009b62c2484145764994a5`，机器记录在 `docs/history/performance-baseline-v5.json`，本地归档在 `deliverables/full-ffn-v5-baseline.zip`、`deliverables/v5-source-baseline.zip` 和 `output/baseline-v5/`。第四版本科必做基线 `d501f0d` 继续保留。

## 实现方式与数值等价

第五版已有奇偶两组 SRAM，但每拍只读取当前 k 对应的一组。第六版完整模式同时读取两组：每个输出通道一条 MAC 累加偶数 k，另一条 MAC 累加奇数 k；k 每次增加 2。相同地址下，两组分别提供相邻输入和权重，不增加 SRAM 宏、端口或中间矩阵搬运。

偏置只加入偶数部分和一次。点积结束后增加一个 MERGE 周期，将两条 40 位部分和相加并寄存，再送入 GELU 或输出 FIFO。这个寄存级避免把新增 40 位加法器直接串到 GELU 的组合路径上。后续正式 STA 仍须检查 SRAM→MAC、部分和合并及 GELU 各路径。

运算采用精确整数，不在乘积或部分和处截断。每个第二层部分和最多包含 128 个 int16 乘积，偶数部分另加 int32 偏置；两者及最终 256 项结果都在 int40 范围内，因此分组累加与原有顺序逐位等价。这一结论不适用于任意浮点重排，但适用于当前冻结整数合同。

完整模式的偏置预取随 k 步长同步调整，仍在当前组计算时预取下一组的八个偏置。第一层独立模式保留原 k 步长、偏置预取、输出 FIFO 和周期；新增 MAC 的累加使能在独立模式关闭。该使能不代表所有组合逻辑都不翻转，不能据此宣称功耗不变。

KWT5 寄存器地址不变；`0x50` 的 MAC 活动周期在完整模式变为 202,752，`0x7c` 的第二层活动周期变为 101,376。这些计数以时钟周期为单位，不能当作乘加运算次数；完整任务仍执行 3,244,032 次矩阵 MAC。

两层继续复用同一组硬件。行间中间缓冲仍是 512 B，GELU 仍为单单元，每组八个结果用八周期处理；未复制第二套完整计算引擎。

## 周期分解

| 互斥阶段，单任务周期 | 第五版 | 第六版 |
| --- | ---: | ---: |
| 主机装载及输入就绪通知 | 79,495 | 79,495 |
| DMA 装载 | 26,567 | 26,567 |
| 计算与最终写回 | 438,800 | **240,007** |
| DMA 控制 | 2 | 2 |
| CPU 配置及观察完成余量 | 790 | 767 |
| 总计 | 545,654 | **346,838** |

CPU 余量的 23 周期差异来自更早完成后与固件轮询、总线仲裁的相位关系，固件和计时边界没有修改。MAC、GELU、等待等活动统计会重叠，不能再累加到这些互斥阶段上。

整机没有达到两倍加速，是因为加载时间、GELU 和控制仍需执行，并且每个输出组增加一次部分和合并。当前主机加载和 DMA 加载合计约占 30.58%，GELU 约占 7.31%；若继续提高算术并行度，收益会进一步受这些环节限制。

额外增加八个 40 位累加器和八个 40 位合并寄存器，以及乘法、加法和选择逻辑。新增硬件在独立模式下仍需计入面积。本次是以逻辑资源换取速度：DMA 引擎通用实例数约增加 57.06%，不宣称面积效率或能耗效率改善。各层级有包含关系，不能重复相加；这些实例数也不能换算成正式 mm²。

SRAM 仍为 2 个 16×4096、34 个 16×1024、4 个 16×128 单端口宏，共 87,040 字节。完整模式会同时活动更多存储分组和乘加单元，瞬时功耗可能增加；任务变短是否降低能耗，需要实际工艺和活动分析。150 MHz、2.25 mm²、整机功耗与能耗仍待官方后端环境验证。

## 验证与复现

- 独立第一层和完整 FFN 各 12 个真实 E203 任务，RTL/综合网表逐位输出与周期一致。
- DMA 压力回归覆盖背压、末笔写响应延迟、读写错误、中止、复位、恢复和不复位切换两种模式。
- 新增三组完整形状、全值域输入测试：同号极值、大幅正负抵消、固定种子随机 int16，以及 int32 偏置极值。RTL、综合网表和 Icarus 四态分别通过 19,008 个输出检查；饱和次数分别为 25,344、12,672、12,573，与软件模型精确一致。
- 原 54,357 组 GELU 检查保留；数学表和算法未变。新增路径通过严格 Verilator `-Wall` lint。
- 真实验证样本最大完整 FFN 聚合 NRMSE 仍为 **0.139819%**，真实样本 GELU 饱和仍为 0。极值测试中的饱和是有意触发并逐项验证的行为。
