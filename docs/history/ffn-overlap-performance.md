# 第七版：数据搬运与 GELU 后台调度

> 本文保留第七版 `eefe431` 的历史结果。当前第八版见 [组间调度优化](../ffn-group-scheduling.md)。

第七版在保持 **16 路乘加单元**的前提下，让 GELU 和下一组第一层计算重叠，并让第一层分块计算覆盖第二层参数 DMA 加载。数学模型、量化格式、GELU 表、共享总线及计时边界不变。

第六版基线为提交 `411a15173dca348be00cb2615661321cb1987199`，机器记录在 `docs/history/performance-baseline-v6.json`，本地归档为 `deliverables/full-ffn-v6-baseline.zip`、`deliverables/v6-source-baseline.zip`、`output/baseline-v6/`。第四、五版基线继续保留。

## 第六版的瓶颈与本轮范围

- 主机装载及通知 **79,495 周期，占 22.92%**。这是当前加载端逐字握手的成本，本轮保持其协议、数据量和计时边界。
- DMA 装载 **26,567 周期，占 7.66%**。原来两层参数全部装载后才启动第一层，第二层权重存在可提前加载并重叠计算的空间。
- GELU **25,344 周期，占 7.31%**。原来每组八个结果串行经过 GELU 时，乘加阵列必须停等。
- MAC 本身 **202,752 周期，占 58.46%**。本轮不增加乘加数量，也不改变数值格式，目标是减少它前后及两组之间的停顿。

## 后台 GELU

第一层每组八个累加结果合并进原有寄存器后，独立的 GELU 工作状态记录该组的行号、列组和处理位置。单个 GELU 单元每拍处理一个结果，写入中间 SRAM；乘加主状态机立即进入下一组 PRIME/MAC。

合并寄存器通过有效状态保护，GELU 未消费完之前不得覆盖。当前下一组乘加所需周期远大于八个 GELU 周期，因而无需复制 GELU 单元或乘加阵列。第二层开始前仍需等待最后一组 GELU 排空，避免读取尚未写入的中间结果。

GELU 总处理量仍为 25,344 项。其中 **22,085 周期**与 MAC 同时活动，其他大部分与 PRIME 重叠。每块末尾的八个 GELU 结果仍需完成；共 13 块，最后一块只有 3 行。统计的是同时活动周期，不能将 GELU 周期再加到整机阶段总和上。

## 八行分块与第二层参数预取

完整模式在 X/W1/b1 的 **11,616 个字**到齐后立即启动第一层。DMA 同时继续读取 W2/b2，写入与第一层计算物理分离的 SRAM；计算期间只允许这些第二层参数写入，不允许覆盖正在使用的 X/W1/b1。

第一层先计算同一块的最多八行，将 GELU 输出暂存。块尾同时满足以下条件后，才能执行第二层：

1. 最后一组 GELU 已写完。
2. W2 的 8,192 个字和 b2 的 64 个字全部收到。

第二层按原行顺序输出整块结果，再复用缓冲计算下一块。最后一块处理第 96—98 行；最终输出依然是原来的 `99×64` 行优先顺序。两层仍复用同一套乘加阵列。

相邻行的首组偏置复用前一行末组已预取的第零组偏置；在两层/分块切换处才重新填充偏置。这样还减少了重复的行首偏置读取停顿。

中间缓冲的两个 `16×128` 宏扩大为两个 `16×1024` 宏，总容量增加 **3,584 字节**，没有增加宏数量或存储端口。当前内部宏组成为 2 个 `16×4096`、36 个 `16×1024`、2 个 `16×128`，合计 **90,624 字节**。中间矩阵仍不读写共享 SRAM。

## 周期分解与统计定义

| 可相加的互斥阶段，单任务周期 | 第六版 | 第七版 |
| --- | ---: | ---: |
| 主机装载及通知 | 79,495 | 79,495 |
| 启动计算前的 DMA 装载 | 26,567 | **15,530** |
| RUN：计算、重叠加载、最终写回 | 240,007 | **214,338** |
| DMA 控制 | 2 | 2 |
| CPU 配置及观察完成余量 | 767 | 924 |
| 总计 | 346,838 | **310,289** |

第七版的 RUN 阶段已包含尾部参数读取，不应将它误称为纯计算耗时，也不能再把尾部加载时长加一次。CPU 余量由总计减去互斥硬件/加载阶段得到，包含调度、仲裁、轮询观察等相位影响。计时内 `main/execute/kwt_linear/kwt_ffn` 的机器码与第六版逐字一致；快照函数增加读取三项统计，位于计时之外。关闭快照后单任务仍为 310,289 周期。

新增 KWT5 只读寄存器：

| 偏移 | 定义 | 正常整机任务结果 |
| --- | --- | ---: |
| `0x88` | GELU 与 MAC 同时有效的周期数 | **22,085** |
| `0x8c` | 块尾 GELU 已排空、但第二层参数未到齐的等待周期 | **2,308** |
| `0x90` | RUN 内尚未收完参数的周期数 | **11,036** |

11,036 周期尾部加载中，8,728 周期由第一层计算及其调度覆盖，剩余 2,308 周期暴露为参数等待。上述三项为诊断统计，会与 RUN、MAC、GELU 等统计重叠。

原 15 项统计、`0x7c/0x80/0x84` 的第二层 MAC/GELU/饱和计数和控制接口保持原语义。新统计在计时结束后由固件复制到 mailbox `0xa000f06c/70/74`。**新版 `kwt_profile()` 目标缓冲区需要 22 个 32 位字**；前 19 字布局不变，word 15 仍为发布标志。使用新版驱动时不能继续只分配原来的 19 字缓冲区。

## 验证及资源

两种模式分别通过 12 个真实 E203 任务的 RTL 和综合网表验证，完整 FFN 的 76,032 个输出、独立第一层的 304,128 个输出逐位一致，综合前后周期和统计一致。

新增定向压力场景将首个 W2 响应延迟 20,000 周期：硬件在 W2 尚未到达时先完成八行第一层、第二层 MAC 计数保持 0，随后解除等待得到正确结果。另覆盖第二层参数读取错误、后台 GELU 启动后的中止、异常恢复、分块末尾、最后三行、不复位模式切换、输出背压和最终写响应延迟。RTL、综合网表及 Icarus 四态均通过。

三组全值域数值测试继续检查极值、正负抵消、随机 int16 和 int32 偏置边界，覆盖 19,008 个输出；真实样本的量化误差保持不变，完整 FFN 最大逐层聚合 NRMSE 仍为 **0.139819%**。没有重新训练、调整量化或改变 GELU 近似。

| 通用逻辑实例数 | 第六版 | 第七版 |
| --- | ---: | ---: |
| 计算核 | 46,115 | **46,335** |
| DMA 引擎，包含计算核 | 53,064 | **53,550** |
| 总线 | 453 | **453** |

DMA 引擎通用实例数增加约 **0.92%**。这些不是物理面积，且 SRAM 黑盒的容量变化不会直接体现在通用实例数里；增大的中间宏仍须按官方面积和功耗模型计入。SRAM 功耗、并行活动功耗、能耗收益、150 MHz 时序和 2.25 mm² 预算仍未正式验证。

## 剩余瓶颈

优化后，MAC 活动约占整机 **65.34%**，主机装载占 **25.62%**，启动前 DMA 装载占 **5.01%**，暴露的第二层参数等待占 **0.74%**。这些数值按各自定义说明瓶颈，GELU 的重叠活动不能额外相加。

继续保持 16 路乘加时，可优先在正式平台确认主机加载端的连续请求能力；本地共享总线已有连续事务能力，但当前主机逐字握手仍占 79,495 周期。其他候选是减少 PRIME/MERGE 的组间空拍、进一步提前第一层启动或减少剩余参数等待。单纯继续复制 GELU 单元的周期收益已经有限，因为大部分 GELU 时间已被覆盖。
