# FIFO 供需分析与输出合并调度实验

本轮先冻结第三版，再观察真实 E203 SoC 的 FIFO 握手和尾段状态，根据数据只改变一处调度。数值格式、16 路 MAC、GELU、FIFO 深度、驱动和硬件向量保持不变。LN1→FFN 输入直传没有混入本轮 A/B。

## 基线保存与测量口径

基线提交为 `59487c7eb255ce8281185f1338d616b9c3f5e245`：

- `deliverables/encoder-v3-59487c7-source.zip`：Git 源码快照。
- `deliverables/encoder-v3-59487c7-baseline.zip`：源码、向量、日志、固件和性能报告，共 **1,855 个文件**，逐文件 SHA-256 及 ZIP CRC 已校验。
- `output/baseline-encoder-v3-59487c7/`：性能报告与已验证日志的独立备份。
- [基线清单](fifo-study-baseline.json)：提交、归档校验值和周期/流量基线，随 Git 保存。大型归档保留在本地，不随 Git 上传。

观察器为 `tests/encoder_fifo_monitor.svh`，仅在定义 `ENCODER_FIFO_METRICS` 的 RTL 仿真中启用，**不新增综合逻辑或 MMIO 寄存器，不增加 CPU 访问**。计数直接采样时钟上升沿实际 valid/ready 握手，窗口从接受 FFN 启动到编码器 tail 成功结束；每层清零。原始第三版加观察器后仍为 **14,561,648 周期**。

定义：空等待 = 消费者 ready 且 FIFO 无 valid；满等待 = 生产者 valid 且 FIFO 无 ready；输入/输出传输分别计实际 push/pop；传输周期取两端发生握手的并集，双向同时传输只计一个周期。峰值取时钟边沿后占用量。观察器检查 `push-pop=occupancy`、传输周期守恒及尾段互斥分类之和，避免把 FIFO 自身空闲误算成消费者等待。

## 是谁限制速度

第三版一条输入执行 12 层的统计：

| FIFO 指标 | 12 层合计 | 每层 |
| --- | ---: | ---: |
| 消费者空等待 | **2,598,648** | **216,554** |
| 生产者满等待 | **0** | **0** |
| 接收 FFN 结果 | 76,032 | 6,336 |
| 编码器取走结果 | 76,032 | 6,336 |
| 实际传输周期（两端并集） | 104,544 | 8,712 |
| 两端同拍传输 | 47,520 | 3,960 |
| 最大占用 | **3/4** | **3/4** |

消费者等待 FFN 供给，生产者没有因这条 FIFO 被阻塞。当前结果不支持增加 FIFO 深度或加快消费端作为优先优化；峰值仅 3，现有 4 深度已经容纳输出突发。

## 尾段时间拆分

| 互斥类别 | 12 层周期 | 含义 |
| --- | ---: | --- |
| 首个结果前等待 | 319,248 | 每层 26,604，含上游装载和首块计算，不等于纯 DMA 时间 |
| 后续结果间等待 | 2,279,400 | 每层 189,950，主要等待 FFN 后续输出 |
| 接收并处理残差元素 | 76,032 | 每层 6,336 个有效结果消费拍 |
| 残差分组控制及 SRAM 保存 | 38,016 | 每层 3,168 拍 |
| LN2 算法阶段 | 218,592 | 每层 18,216 拍，包含迭代数学和必要控制 |
| 最终输出阶段 | 8,461 | 仅最后一层写回；包含读缓存、DMA 和等待 |
| 未分类周期 | 0 | 守恒检查必须为零 |
| **尾段总计** | **2,939,749** | 与原编码器命令周期逐层一致 |

等待 FFN 合计占尾段 **88.40%**；非等待的残差/控制/LN2 为 **332,640 拍**，最终输出为 8,461 拍。这些等待与上游执行重叠，不能把它们和 FFN 周期相加，也不能直接将 88.40% 宣称为可获得的提速空间。

FFN 每层执行 226,131 拍，其中 MAC 活动 **202,752 拍（89.66%）**；第二层权重未就绪的独立屏障等待为 2,548 拍。FFN 状态直方图还显示每层 3,960 个 MERGE 拍，其中 3,168 个为第一线性层进入 GELU，792 个为第二线性层输出。完整逐层直方图保存在机器报告中。

## 本轮唯一的结构改动

选择消除输出组的独立 MERGE 拍：在原有 EMIT 拍将 `even_acc + odd_acc` 直接写进已有输出 FIFO，LAST 后直接进入 EMIT。进入 GELU 的第一层仍保留独立的合并寄存器和原有顺序。

FIFO 接受前累加器保持不变；接受边沿的非阻塞赋值先取旧部分和，再初始化下一组。没有提前舍入、缩放或饱和。独立第一线性层也使用这条输出路径。`KWT_BASELINE_OUTPUT_MERGE` 编译宏恢复旧调度，供同条件复现。

每层 FFN 和 tail 等待各减少 **792 拍**，12 层硬件累计各减少 **9,504 拍**；两者重叠，不能累加成 19,008 拍。有效 MAC、GELU、FIFO 深度、传输数量、残差控制和 LN2 周期不变。该改动检验的是输出调度收益，并未解决主要计算量。

## 同条件实测对照

| 工作负载 | 第三版基线 | 当前候选 | 周期减少 |
| --- | ---: | ---: | ---: |
| 完整 12 层编码器 | 14,561,648 | **14,549,345** | **12,303（0.08449%）** |
| 第一线性层独立模式 | 170,236 | **167,134** | **3,102（1.822%）** |
| 完整 FFN 独立模式 | 306,703 | **305,708** | **995（0.3244%）** |

完整任务确实减少周期，但幅度较小，与本轮只移除输出调度拍的范围一致。整机节省 12,303 拍，而 12 层 FFN 命令累计节省 9,504 拍；其余差值来自同一固件/测试平台轮询与完成观察的相位变化，不能算成额外的计算节省。主机按 1,024 拍间隔轮询，每次事务另有总线开销。该整机周期收益对应当前固定调度，不能外推为任意软件下的同等收益。

候选每层尾段空等待为 **215,762**，首结果前为 **26,603**、结果间为 **189,159**；满等待仍为零，最大占用仍为 3/4。完整任务 DMA 仍为 **489,600 个32位字**，本轮没有再减少搬运量。150 MHz 目标下折算 **96.996 ms/次**，不代表工艺 Fmax 已验证。

两个独立模式均覆盖 12 个任务。候选编码器覆盖 12 条输入 × 12 层，基线用同一条 task 0 输入完成 12 层 A/B，并核对历史 12 条基线均为相同周期。最终整数输出逐位一致，所有层的饱和计数为零。全范围 FFN、紧凑40位/直传、背压、中止排空与恢复在 Verilator/Icarus 中通过；严格 lint 通过。逐层分解、状态/占用直方图、输入与日志校验值见 [机器验证报告](fifo-study-validation.json)。

## LN1→FFN 输入直传的后续实验

此方案已在第五版实现，结果见 [输入直传报告](input-stream.md)；以下保留第四版提出实验时的验证要求。

本轮保留现有 packed int16 输入 SRAM 交接。后续单层实验应先建立可切换的 SRAM 对照，避免直接改整个 12 层调度：

1. **权重就绪**：分别定义 W1/b1 与 W2/b2 的完整装载有效位；未就绪时保持背压，不允许消费旧任务权重或提前启动 MAC。
2. **输入分块**：输入固定为 99×64 个 int16，共 3,168 个32位字。可先沿用现有8行 tile：12个完整块各256字，最后3行96字；定义块编号、块完成和末块长度，只有完整接收的块才可计算，沿用原输入量化结果。当前 X 存储体为单端口，不能在第一层 MAC 读取时任意写下一块；应先验证利用第二层计算窗口装载下一块的仲裁与就绪屏障，不能仅放宽 `dma_load_ready`。
3. **背压**：随机延迟权重、输入和消费者，检查 stalled valid 时数据/索引保持，分别覆盖 FIFO 空、满和同拍出入。
4. **取消与重启**：分别在权重未就绪、块中间、末字受阻、开始计算后取消；排空已接受总线事务，清块有效位和队列，随后新任务不能读到旧输入。
5. **评价**：先单层逐位核对中间结果、完整输出及字数，再做真实 E203 同固件完整任务计时。可以减少每层写/读各 3,168 字，但能否更早启动计算取决于权重与分块调度，不能仅凭减少搬运判定加速。

## 复现

已有模型向量、工具与固件时：

```powershell
# 同一源码/同一固件，只以编译宏切换输出合并调度。
.venv-model\Scripts\python.exe scripts/run_fifo_study.py baseline
.venv-model\Scripts\python.exe scripts/run_fifo_study.py candidate --tasks 12 --jobs 4
.\encoder.ps1 compat
.\encoder.ps1 lint

# 改动计算核后，基础模块和四态检查也需重跑。
.\design.ps1 accel
.\design.ps1 ffn
.\design.ps1 dma
.\design.ps1 fourstate
.\encoder.ps1 transfer
.\encoder.ps1 collect
.\encoder.ps1 package
```

`fifo-baseline`、`fifo-profile` 是前两条命令的 PowerShell 别名。报告校验同固件/同向量、仅一个 RTL 算法模块变化、逐层计数守恒和两个独立模式无回退；输入指纹在编译前保存。首次实测的基线是未经修改的第三版 RTL，其指纹在基线编译完成、候选修改前保存；后续复现用同一源码加编译宏恢复旧调度。

数值格式和整数数学文件保持冻结；本轮不重新运行 4,445 条软件分类评估。没有新增综合、网表或 PPA 结论。
