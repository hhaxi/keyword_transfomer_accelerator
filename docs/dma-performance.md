# 第三版：DMA、连续传输与周期分析

本页保留第三版历史结果；当前实现及寄存器格式见 [第四版性能分析](parallel-packed-performance.md) 和 [架构说明](architecture.md)。复现本页结果请使用提交 `e85a6899ac7c363ecf9dcce3809bfeaa80ccd41d`，当前工作区执行下列命令会验证第四版。

第三版保留四路 MAC、8 项输出 FIFO、52 KiB 内部 SRAM 和冻结数值格式，增加自主参数加载、结果写回和周期统计。CPU 负责配置及通知，全部矩阵计算与输入输出搬运由硬件完成。共享 SRAM 仍为 512 KiB 同步单端口。

## 周期分解

以下互斥阶段可直接相加，12 个任务的结果一致：

| 阶段 | 周期 | 说明 |
| --- | ---: | --- |
| 主机装载及输入就绪通知 | 91,907 | 包括 X/W/b 写入共享 SRAM 与 mailbox=1 |
| DMA 参数加载 | 30,717 | 读取 22,976 个字并写入内部 SRAM，含仲裁等待 |
| 计算与结果写回重叠阶段 | 468,879 | 最后一个写响应返回才结束 |
| DMA 控制转换 | 2 | 清空核心有效状态及启动计算 |
| CPU 配置和完成观察余量 | 761 | 整机总周期减去上述阶段，含通知与主机轮询观测 |
| **总计** | **592,266** | 与整机计时相等 |

DMA 内部总周期为 **499,598 = 30,717 + 468,879 + 2**。诊断计数中：四路 MAC 同时有效 **405,504 周期**，计算核从启动到最后输出取走 **468,874 周期**，FIFO 满等待 **0 周期**，DMA 请求等待 **23,511 周期**。这些诊断项彼此重叠，不能再次加到总耗时中。

结果写回已经能跟上当前计算核。无背压的计算调度预算为 `6,336 × 74 = 468,864` 周期，与实测重叠阶段接近；进一步提升吞吐将更多依赖计算调度、并行度与资源代价，而不是继续扩大输出 FIFO。

## 硬件行为

- DMA 有一个寄存的待发请求和最多一个已接受事务。请求被阻塞时地址、数据、读写方向和掩码保持；旧响应完成与新请求接受允许同拍。
- 输入 DMA 连续读取 X/W/b，响应直接写入计算核 SRAM；完整收到全部参数才启动计算。每任务均重载，不能把跨任务缓存算作免费命中。
- 输出 DMA 从核心 FIFO 接收 64 位符号扩展结果，拆成两个 32 位写事务。只有 50,688 个成功写响应全部返回才置位 done；最终写响应出错必须报告失败。
- 总线在 CPU、外部加载端和 DMA 间轮转，保持一个响应槽并支持同拍退役/接收。受控测试连续 128 个请求耗时 129 周期（含流水填充/排空），出现 **128 拍连续接收**；三个主设备持续请求时无仲裁空拍。
- 中止、读错误、写错误先停止生成请求，再排空已经发出及已接受的事务，最后清空核心。已经提交到共享 SRAM 的部分输出不回滚；软件等待 busy 清零后才可重新使用缓冲区。

## 统计寄存器

偏移相对 DMA 基址 `0x40000000`，均为只读 32 位。每次正常启动清零，任务完成后冻结；应在 idle/done 后读取一致快照。当前固定任务远小于计数器回绕范围；任意长时间外部阻塞下计数器按 32 位回绕。

| 偏移 | 名称 | 定义 |
| --- | --- | --- |
| `0x40` | dma_total | DMA 启动被接受后至完成/错误排空结束的周期 |
| `0x44` | load | 参数加载阶段周期 |
| `0x48` | compute_writeback | 计算与写回阶段周期 |
| `0x4c` | control | 其他活动阶段周期，正常完成时为 2 |
| `0x50` | mac_active | MAC/最后一项排空状态周期，每拍四路有效 |
| `0x54` | fifo_full_wait | 核心无法一次入队四项的等待周期 |
| `0x58` | core_elapsed | 核心启动至最后一个结果被 DMA 取走 |
| `0x5c` | dma_request_wait | 主请求 valid 且 ready=0 的周期 |
| `0x60` | dma_response_wait | 主响应 valid 且 ready=0 的周期；当前 DMA 始终接收，值为 0 |
| `0x64` | dma_read_commands | 已接受的读请求数，完整任务 22,976 |
| `0x68` | dma_write_commands | 已接受的写请求数，完整任务 50,688；失败时不代表全部成功 |
| `0x6c` | first_output | DMA 接收第一个核心输出的时间戳 |
| `0x70` | last_output | DMA 接收最后一个核心输出的时间戳 |
| `0x74` | last_write_ack | 最后写响应成功返回的时间戳，应等于 dma_total |
| `0x78` | producer_wait | RUN 中输出保持寄存器空且核心尚无结果的周期 |

时间戳以 DMA 启动为零点。主机先停止计时，再请求 mailbox=3；固件将 15 项统计复制到 `0xa000f020..0xa000f058`，写入发布标志，最后回复 mailbox=4。整个统计采样在任务测量之外。

错误排空和空闲时的清理会清空计算核的三项统计（`0x50/0x54/0x58`）；完整的核心周期分析以成功任务为准。DMA 自身统计在退出 busy 后保留至下一次启动或复位。

## 验证与资源边界

- 核心 RTL/网表及 E203 整机 RTL/网表各完成 12 组、304,128 个输出的逐位检查；整机周期和全部 15 项统计综合前后一致。
- DMA 独立测试覆盖错位/越界/重叠地址、忙时非法操作、请求与响应延迟、读错误、首个及最后写错误、未接受请求中止、未完成事务中止、读写期间复位，以及故障后完整重跑。刻意阻塞写回时 FIFO 等待计数确实增加。
- 总线测试覆盖连续吞吐、三方竞争、响应背压、目标阻塞时授权保持、主设备访问范围保护及复位；RTL 和综合网表均验证。Icarus 另做四态核心、DMA 和总线检查。
- 通用综合实例数：计算核 **11,375**；含计算核的 DMA 引擎 **16,027**；独立总线仲裁/路由 **453**；完整本地 SoC **35,100**。这些是不同层级统计，DMA 数字已包含计算核，不能重复相加。实例包含宏和作用域记录，不能视作工艺面积。
- 正式加速器面积必须计入 DMA、新增接口/仲裁和内部 SRAM，不能只报告计算核。实际面积、时序、功耗与能耗仍待官方平台、工艺库及统一评测条件。
- 第一版活动文件已归档，第三版没有复用旧活动文件；正式功耗分析须重新采集第三版完整任务并检查 SRAM 模型与活动覆盖。
