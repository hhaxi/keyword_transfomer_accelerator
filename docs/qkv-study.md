# QKV 投影周期瓶颈研究（f7a3a47）

本轮保留编码器 v5 / FFN v10 的生产 RTL、固件和冻结数值格式。新增可关闭的仿真观测器，先测量单层，再统计同一基线的十二层；没有推出新的调度实现。结论是：QKV 已接近现有 4 路 32 位乘法通路的吞吐下限，局部调度优化的理想收益不足完整十二层任务的 **0.40%**，因此按“收益有限不强行修改”的要求保留基线，提交统计工具、证据和候选方案。

这里的十二层运行是基线瓶颈验证，不是未经单层收益验证的优化扩展。16 路 FFN MAC、4 路编码器乘法通路、122 个内部 SRAM 宏及原有数值运算顺序全部未改。

QKV 继续使用 int32 操作数、72位累加、右移16位的最近偶数舍入及 int32 饱和；后续缩放与残差顺序保持原样。

## 1. 条件和计数口径

- 基线：`f7a3a47d48c5581319d580d98f7145515976ee06`。
- E203 完整 SoC；99 token、64 维、单头；`transport=2`、`input_stream=1`、`baseline=0`；task 0。
- 同一固件、同一冻结向量、同一仿真可执行文件。`+qkv_stats=0` 关闭观测，默认开启；它不控制硬件。
- 硬件原有 `phase_cycles[0]` 统计 QKV 计算，`phase_cycles[7]` 统计前段全部 DMA 装载。权重装载不属于 QKV 计算阶段，另行归因。
- 观测器按时钟上升沿读取更新前状态，与 RTL 周期计数一致；命令完成后逐项检查与硬件阶段计数相等。
- MAC/首读/初始化/结果写回/其他等待是互斥周期。SRAM 读事件、预读与计算重叠、DMA 请求/响应等待是事件统计，不能再加到互斥周期之上。
- 完整任务周期包含主机输入/参数加载、CPU 调度、硬件运行、最后写回和完成通知观察；不含固件初次加载及计时后的输出核对。主机每 1,024 拍轮询，因此硬件窗口缩短不保证整机恰好缩短同样拍数。

## 2. QKV 计算阶段

每层三个投影的计数完全相同：

| 互斥分类 | 单个投影 | Q+K+V 合计 | 解释 |
| --- | ---: | ---: | --- |
| 有效 MAC | 101,376 | 304,128 | 每拍 4 个有用乘加，包含零值乘法，不按数值跳过 |
| 独占 SRAM 首读 | 1 | 3 | `PPRIME`，第一组操作数同步读 |
| 状态初始化 | 1 | 3 | `PINIT`；其余组初始化已并入写回 |
| 结果写回 | 1,584 | 4,752 | `PSAVE`，每次写出 4 个 int32 |
| 其他计算等待 | 0 | 0 | 没有额外组间等待或乘法器空泡状态 |
| **阶段总周期** | **102,962** | **308,886** | 与阶段 0 完全相等 |

有用标量乘法数为 `3 × 99 × 64 × 64 = 1,216,512`，四路通路至少需要 `1,216,512 / 4 = 304,128` 拍。阶段内有效利用率 **98.4596%**。这里指固定矩阵运算的有用工作量，不是开关活动或功耗利用率。

SRAM 预读实际上已充分重叠：

| 事件（不能与上表重复求和） | 单投影 | 每层 QKV |
| --- | ---: | ---: |
| 在 MAC 拍预读下一 k 的 X/W | 99,792 | 299,376 |
| 在结果写回拍预读下一组 X/W | 1,583 | 4,749 |
| 第一组独占预读 | 1 | 3 |
| X 读32位字数 | 101,376 | 304,128 |
| W 读32位字数 | 405,504 | 1,216,512 |
| Q/K/V 结果写32位字数 | 6,336 | 19,008 |

X 每拍读一个32位数并广播至四路 MAC；W 同拍读四个32位权重。最后一个 k 已无需继续读 W，所以每组末 MAC 拍 W 端口空闲，紧接着的写回拍已读下一组首操作数。增加一般性的“组间预读状态”会重复现有工作。

## 3. 装载与等待

首层的真实 SoC 测量如下，全部来自阶段 7 的细分，未把初始 X 或归一化参数冒充 QKV 权重：

| 装载对象 | 32位字数 | 周期 | 请求未获 ready | 有在途但无响应 |
| --- | ---: | ---: | ---: | ---: |
| 初始 X | 6,336 | 8,460 | 2,123 | 0 |
| 公共参数（偏置及 LN） | 320 | 428 | 107 | 0 |
| Q 权重 | 4,096 | 5,468 | 1,371 | 0 |
| K 权重 | 4,096 | 5,470 | 1,373 | 0 |
| V 权重 | 4,096 | 5,469 | 1,372 | 0 |
| O 权重 | 4,096 | 5,469 | 1,372 | 0 |
| **阶段 7 合计** | **23,040** | **30,764** | **7,718** | **0** |

请求等待与“发出/回收”动作可重叠，不能与周期列相加。具体的互斥分解：

| QKV 权重 | 仅发出 | 仅回收 | 同拍发出并回收 | 两者均无 | 总周期 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Q | 1,367 | 1,367 | 2,729 | 5 | 5,468 |
| K | 1,368 | 1,368 | 2,728 | 6 | 5,470 |
| V | 1,369 | 1,369 | 2,727 | 4 | 5,469 |

三个投影权重装载合计 **16,407 拍**。每类权重都只搬入一次，再供 99 行复用。两笔 DMA 信用耗尽导致停发的计数为 0，响应等待也为 0；此测量中的瓶颈在请求接纳一侧，继续增加 encoder DMA 在途深度没有直接证据支持。

Q/K/V 权重装载期间 FFN 获准发出请求的计数均为 0，说明 v5 的预装载避让已经生效。初始 X 装载期间仍有 1 笔既有 FFN 请求排空，这是允许行为。共享总线还服务 CPU 和主机，并采用轮转仲裁；当前观测没有把每个请求停顿进一步分到 CPU、主机或响应槽，不能把全部请求等待直接归咎于某一个主设备。后续总线实验应先补充 grant/slot 归因。

## 4. 可消除开销和收益上限

以下是**硬件关键窗口的乐观估算**，不是已实现的性能提升，也不承诺轮询计时下的精确整机差值。

1. **仅改 QKV 计算调度：**即使消除所有首读、初始化和写回气泡，每层也最多省 `308,886 − 304,128 = 4,758` 拍。单层完整任务的上限约 **0.3864%**；十二层最多省 **57,096 拍，约 0.3989%**。现实实现仍需要启动/最后结果排空，通常达不到此理想值。
2. **理想每拍接纳一个权重字：**首层 QKV 装载从 16,407 拍降到至少 12,288 拍，最多再省 **4,119 拍**；十二层相应预算 **49,439 拍，约0.3454%**。这属于总线/CPU 交互优化，不能归入乘法器或 SRAM 预读优化；同时必须保留其他主设备的进度。
3. **把全部 QKV 权重装载完全隐藏：**首层极乐观总预算为 `4,758 + 16,407 = 21,165` 拍，约单层任务的 **1.7190%**。十二层 QKV 权重实际装载合计 **196,895 拍**，加上调度开销的极乐观预算为 **253,991 拍，约1.7743%**。该假设需要不同的存储/调度方案，现有单份 W SRAM 无法简单双缓冲，首层 Q 的启动依赖也仍存在。

不能同时把“全部装载隐藏”和“装载等待消除”相加，两者覆盖同一窗口。QKV 在十二层任务中占比约 25.89%，但其中绝大多数是固定乘法工作；它不是一块可整体消除的等待时间。

## 5. 数据复用与候选方案

| 候选 | 可以改变什么 | 限制与本轮决定 |
| --- | --- | --- |
| 上一组写回与下一组首 MAC 重叠 | 保留四路乘法器，将最终累加值的写回与新组累加器初始化并行，最多接近每组省1拍 | 需要保存/推导上一组写地址、处理投影边界和取消；整个任务上限不足0.4%，本轮不加入新硬件分支 |
| 降低 CPU 轮询争用，或调整 DMA 仲裁 | 减少权重请求端停顿；首层理想预算4,119拍 | 先补 grant/slot 统计；需证明 CPU、主机不饥饿，并维持同一任务计时口径 |
| 借既有空闲存储区域预装 K/V 权重 | 可能隐藏部分 K/V 装载，单层理想预算10,939拍 | 要重新规划各矩阵生存期和地址、读写冲突、取消恢复；不是给现有 W bank 简单加预读，尚无实测收益 |
| 缓存一行 X，或扩展多行/多组累加驻留 | 减少重复片内读，可能降低某些存储访问计数 | 当前 MAC 已逐拍供满，不能突破304,128拍计算下限；新增寄存器或部分和搬运需另算，不能据此宣称功耗降低 |
| 增加 DMA 信用或再插入预读状态 | 当前测量没有显示能消除的等待 | 信用满等待为0、操作数预读已重叠，不实施 |

降低轮询频率也不等于降低 CPU 总线负载：简单加入忙等仍可能持续取指。需要区分状态寄存器访问、共享 SRAM 取指和响应槽占用，再选择方案；若考虑休眠等待，还要先有可用的完成唤醒路径，不能直接替换为无法唤醒的等待指令。

单端口约束尤其重要：同一个 W 缓存在一个投影的 99 行中反复使用，提前覆盖会破坏后续行。只有最后一行读完的旧权重才可释放；测得最后一行 W 端口仅空闲 **17 拍/投影**。沿用每拍写一个32位权重的装载方式，单靠这些空隙容不下下一投影的 **4,096 字**。改变循环顺序可以提前释放部分权重，但需要更多驻留部分和或额外 SRAM 读写，必须重新估算，而不是假定免费重叠。

X 目前每个值广播给四个输出列，16个列组仍会重复读；W 在片内为每行重复读取。缓存/重排可以改变访存量，不能改变相同四路 MAC 的运算量。跨 Q/K/V 的进一步 X 复用还会涉及三套权重驻留与切换，受当前单份16 KiB投影权重缓存约束。
